# Запуск Dastarhan локально

## Требования
Node 20+, pnpm 9, Docker.

## Первый запуск — четыре команды

```bash
# 1. База данных (Postgres на порту 5433, Redis на 6380)
docker compose -f docker-compose.dev.yml up -d

# 2. Переменные окружения
cp .env.example .env
# открой .env и впиши JWT_SECRET (любая случайная строка от 32 символов)

# 3. Зависимости + схема + демо-данные
pnpm setup

# 4. Запуск
pnpm dev
```

После этого:

| Что | Адрес |
|---|---|
| API | http://localhost:3000/api/v1 |
| Проверка живости | http://localhost:3000/api/v1/health |
| Касса | http://localhost:5173 |
| Бэк-офис | http://localhost:5174 |
| Просмотр базы | `pnpm db:studio` |

## Демо-доступ после сида

Демо-кафе «Дастархан», кассир — PIN `1234`.

## Отдельные команды

```bash
pnpm dev:api        только API
pnpm dev:office     только бэк-офис
pnpm dev:pos        только касса

pnpm db:push        применить схему без миграции (быстро, для разработки)
pnpm db:migrate     создать миграцию (для продакшена)
pnpm db:seed        залить демо-данные заново
pnpm db:studio      GUI для базы

pnpm test           прогнать все тесты
pnpm build          собрать всё на продакшен
```

## Если что-то не работает

**`pnpm setup` падает на db:push** — не поднялась база. Проверь: `docker ps | grep dastarhan-db`

**API не стартует** — проверь `DATABASE_URL` в `.env`, порт должен быть **5433**, а не 5432.

**Порт 5433 занят** — поменяй в `docker-compose.dev.yml` и в `.env` синхронно.

**Касса или офис показывают демо-данные** — значит API не отвечает. Запусти `pnpm dev:api` и посмотри ошибку.
