# РАЗВЁРТЫВАНИЕ DASTARHAN — от нуля до работающей точки

_Модель развёртывания — из анализа 5 конкурентов: облако (как Poster/QuickResto), НИКАКОЙ базы на точке клиента (антипример Paloma: владелец сбрасывает пароль MySQL через cmd). На точке — только приложение кассы с активацией ключом (образец QuickResto)._

## 1. Сервер (30 минут, один раз)

**VPS в Казахстане** (латентность + закон о персональных данных): ps.kz или hoster.kz.
Минимум для старта (до ~50 точек): 2 vCPU, 4 ГБ RAM, 60 ГБ SSD, Ubuntu 24.

```bash
# на сервере
apt update && apt install -y docker.io docker-compose-v2 git
git clone <ваш-репозиторий> dastarhan && cd dastarhan/deploy
cp .env.example .env && nano .env        # заполнить: пароли, домен, ключи
docker compose -f docker-compose.prod.yml up -d --build
docker compose exec api npx prisma migrate deploy   # миграции
docker compose exec api node packages/db/seed.js    # демо-кафе (опц.)
```

DNS: A-запись `app.dastarhan.kz` → IP сервера. Caddy получит TLS сам.

**Проверка сервера:**
- `curl https://app.dastarhan.kz/api/health` → `{"ok":true}`
- `docker compose ps` → все контейнеры healthy
- через 6 часов в `deploy/backup/` появится первый `dastarhan_*.sql.gz`

## 2. Касса (10 минут на точку)

### Android-планшет (основной путь)
1. Установите APK Dastarhan POS (сборка: `pnpm -C apps/pos build && npx cap sync android && открыть в Android Studio → Build APK`; позже — Play Market).
2. При первом запуске: адрес сервера + **ключ терминала** (создаётся в бэк-офисе: Настройки → Кассы → Добавить, лимит по тарифу).
3. Принтер: Xprinter/Epson по Ethernet или USB-OTG — касса найдёт сама (ESC/POS).

### Windows-моноблок
`pnpm -C apps/pos tauri build` → установщик `.msi`. Дальше те же шаги 2–3.

**Касса работает офлайн полностью**: заказы, чеки, печать. Интернет нужен для синка и фискализации (чеки догоняют очередью).

## 3. Чек-лист запуска точки (онбординг ≤15 минут — мастер в бэк-офисе)

| # | Шаг | Проверка |
|---|---|---|
| 1 | Реквизиты (БИН, язык ru/kk) | сохранены |
| 2 | Меню: 5+ позиций (или Excel/сканер для магазина) | плитки видны на кассе |
| 3 | Кассир с PIN | вход по PIN на кассе |
| 4 | Способы оплаты: наличные + Kaspi | видны на экране оплаты |
| 5 | Webkassa: логин/пароль/номер кассы (или «пропустить») | тестовый чек SENT, ссылка ОФД открывается |
| 6 | Принтер чеков | пробный чек напечатан |
| 7 | **Контрольная продажа**: заказ → оплата наличными со сдачей → чек | в бэк-офисе появилась продажа, остатки списались |
| 8 | Контрольный офлайн: выключить Wi-Fi → продажа → включить | событие досинкалось, чек дофискалился |

Пункты 7–8 обязательны: это приёмка точки.

## 4. Эксплуатация

- **Обновления**: `git pull && docker compose up -d --build` (миграции — `prisma migrate deploy`). Кассы обновляются пакетом приложения.
- **Мониторинг**: `/api/health` дергать раз в минуту (UptimeRobot бесплатно); алерт в Telegram владельцу платформы.
- **Восстановление**: `gunzip -c backup/dastarhan_X.sql.gz | docker compose exec -T postgres psql -U dastarhan dastarhan`.
- **Масштабирование**: до сотен точек — вертикально (RAM/CPU); дальше — вынести Postgres в managed и добавить реплику API. Схема готова (stateless API, вся сессия в JWT/Redis).

## 5. Безопасность (минимум, встроено)

- Postgres/Redis не торчат наружу (только внутренняя сеть compose).
- TLS всюду (Caddy). JWT 15 мин + refresh. PIN-хэши argon2.
- Бэкапы с ротацией 14 дней; раз в неделю копируйте свежий вручную в другое место (или S3 — переменные готовы).
